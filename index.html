Page 1

What the gate does

The repository holds one small shell script, sandbox.sh. It starts the Brave browser inside Firejail, so Brave runs with a private home view and the sandbox profile restrictions instead of the real home directory.

The refusal

If the sandbox cannot be provided, the browser does not start at all. A missing firejail is a broken promise, not a reason to launch Brave bare.

Page 2

The two inspections

First, firejail. The script looks for firejail on PATH. If it is absent it prints to stderr that firejail is not installed, warns that Brave would run unsandboxed, and exits with code 1.

error: firejail is not installed, so Brave would run unsandboxed. Install firejail first.

Second, brave. If brave is not on PATH, the script prints that error and exits the same way, with code 1.

error: brave is not installed (or not on PATH).

The order is the point of the page: firejail is checked before brave, because a missing sandbox is the failure that matters.

Page 3

Making a crossing

./sandbox.sh
./sandbox.sh https://example.com

Run the script, followed by whatever you bring with you. Every argument is handed through untouched, quoted as "$@", so a URL or a flag opens directly in the sandboxed browser, and an argument containing spaces stays a single argument.

Page 4

Small print at the back of the ledger

The script sets set -u, so an unset variable fails loudly in a future edit. It checks with command -v, because that searches PATH the same way the shell will. It finishes with exec, so the shell is replaced by firejail rather than lingering as a wrapper, which leaves Ctrl+C and the exit code belonging to the browser run itself.
